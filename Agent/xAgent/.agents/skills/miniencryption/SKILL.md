# miniEncryption 加密保存

## 何时使用

用户使用了以下触发词（或含义相同的表述）时，**必须**加载并使用本技能：

- 「加密保存」
- 「加密后保存」
- 「用 miniEncryption 加密」
- 「把这段文字加密保存下来」

触发词出现即视为明确指令，不要再反问用户是否需要加密。

> 注意：本技能只做**数字 → 中文数字**的替换，不是密码学意义上的加密，不要在回答中宣称它具备安全性。必要时向用户说明这一点。

## 加密规则

把文本中出现的每一个阿拉伯数字字符，按下表一对一替换为对应的中文数字字符。

| 阿拉伯数字 | 替换结果 |
| ---------- | -------- |
| 0 | 零 |
| 1 | 一 |
| 2 | 二 |
| 3 | 三 |
| 4 | 四 |
| 5 | 五 |
| 6 | 六 |
| 7 | 七 |
| 8 | 八 |
| 9 | 九 |

规则要点：

1. **逐字符替换**：逐位替换每一位数字，不按数值合并。例如 `2026` → `二零二六`，不是「二千零二十六」。
2. **只替换阿拉伯数字**：字母、标点、空格、换行、中文汉字等全部原样保留，不得改动。
3. **保留结构**：缩进、空行、行尾换行符、文件整体格式都要保持不变。
4. **全角数字 `０-９`（U+FF10–U+FF19）**默认不替换；若用户明确要求，可与半角数字同样处理。
5. 这是**单向混淆**，没有配套的「解密」规则（信息有损），不要提供反向还原。

## 执行流程

1. **确认输入来源**：
   - 用户直接给出文本 → 加密该文本；
   - 用户给出文件路径 → 先用 `readFile` 读取原文，再加密。
2. **确认输出目标**：
   - 用户未指定路径时，默认在工作目录下新建文件，文件名建议为 `encrypted.txt`；若同名文件已存在，改用 `<原名>-加密.txt` 或询问用户。
3. **做替换**：按上表逐字符替换，或使用等价命令，例如：

   ```sh
   python3 -c "
   table = str.maketrans('0123456789', '零一二三四五六七八九')
   print(open('input.txt', encoding='utf-8').read().translate(table), end='')
   "
   ```

   也可以直接用 `createFile` / `editFile` 写入替换后的内容。
4. **保存结果**：用 `createFile`（新文件）或 `editFile`（已有文件，`overwrite`）写入。
5. **汇报**：告诉用户保存路径、共替换了多少个数字字符，并给一句简短的前后对照示例。同时提醒：这只是数字替换式的混淆，不适合作为真正的保密手段。

## 示例

输入：

```
订单号 20260115，共 3 件，合计 1280 元。联系电话：13800001234
```

加密保存后：

```
订单号 二零二六零一一五，共 三 件，合计 一二八零 元。联系电话：一三八零零零零一二三四
```

## 边界情况

- **文本中没有数字**：原样保存，并告知用户未发现需要替换的数字。
- **用户说「加密」但没说「保存」**：先询问是否要写入文件，不要擅自落盘；只有明确出现「加密保存」时才直接保存。
- **二进制文件 / 超大文件**：先拒绝并说明原因，建议用户先转成文本或缩小范围。
- **小数、负数、日期**：同样逐位替换（`3.14` → `三.一四`，`-5` → `-五`），单位与符号保留。
